# PR 및 이슈 관리 규칙

## PR(Pull Request) 관리
- PR 제목: [타입] 간단 요약 (예: feat: 로그인 기능 추가)
- PR 설명: 변경사항, 테스트 방법, 관련 이슈 명시
- PR 생성 시 자동 라벨, Assignee, Reviewer 지정
- PR 생성 시 자동 코멘트 등록
- main 브랜치 대상 PR은 반드시 1인 이상 리뷰 승인 필요
- CI 테스트 통과 필수
- WIP(작업중) PR은 [WIP] 접두사 사용

## 이슈 관리
- 이슈 제목: [타입] 간단 요약 (예: bug: 로그인 오류)
- 이슈 템플릿 사용 권장
- 이슈 생성 시 자동 라벨, Assignee 지정
- 이슈 생성 시 자동 코멘트 등록
- 완료된 이슈는 반드시 close 처리

## 라벨 정책
- feat: 기능
- fix: 버그수정
- docs: 문서
- chore: 기타
- test: 테스트
- refactor: 리팩터링
- bug: 버그
- enhancement: 개선

## 기타
- 모든 커밋/PR/이슈는 한글 또는 영어로 명확하게 작성
- 코드리뷰는 건설적 피드백 중심
